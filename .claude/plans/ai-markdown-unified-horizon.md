# 修复 AI 优化中 Markdown 格式丢失问题

## Context

AI 优化简历文本时，有时会丢失原始行中的 Markdown 格式标记（如 `**加粗**`、`||` 分隔符等）。当前的 `ensurePrefix` 函数只处理行首前缀（`-`、`#` 等），对内联格式完全无感知。需要让 AI 输出保持与原始行的格式一致性。

## 方案：Prompt 增强 + 用户消息格式注入 + `||` 后处理兜底

### 1. 强化系统 Prompt 中的格式保留指令

**文件：`api/ai/prompts.ts`**

将社招和校招 prompt 中的"步骤 2.5: 格式保留"从一句话改为带具体示例的规则：

- 列出行首前缀、`**加粗**`、`||` 分隔符、`` `代码` ``、`[链接]()` 五种格式的保留规则
- 添加正确/错误示例对比
- 在质量检查清单末尾追加格式保留检查项

### 2. 用户消息注入检测到的内联格式

**文件：`api/ai/optimize.ts`**

- 新增 `detectInlineMarkdown(text)` 函数，检测原文中的：
  - `**加粗**` 对 → 报告完整片段
  - `` `代码` `` 对 → 报告完整片段
  - `[文字](url)` 链接 → 报告完整片段
  - `||` 分隔符 → 报告左右两侧内容
- 在用户消息末尾追加检测结果，给 AI 明确的格式锚点：
  ```
  需要优化的内容：
  - 基于 **Vue + Element UI**，开发模块

  检测到的内联格式（必须在输出中保留）：
  - 加粗: **Vue + Element UI**
  ```

### 3. 前端 `||` 分隔符后处理

**文件：`src/components/editor/AIOptimizeDialog.tsx`**

- 新增 `ensurePipeSeparator` 函数：如果原文有 `||` 但 AI 结果丢失了，自动从原文取右侧内容（通常是日期/元数据）追加回去
- 串联到现有 `ensurePrefix` 中，所有调用点自动受益

### 不做的事

- **不对 `**bold**` 做前端后处理**：AI 重写后文本变了，无法确定哪些词该加粗，强制注入会出错
- **不改流式架构**：只改预计算的 prompt 和最终输出的后处理

## 修改文件清单

| 文件 | 改动 |
|------|------|
| `api/ai/prompts.ts` | 强化步骤 2.5 格式保留指令 + 质量检查清单追加 |
| `api/ai/optimize.ts` | 新增 `detectInlineMarkdown` + 用户消息追加格式上下文 |
| `src/components/editor/AIOptimizeDialog.tsx` | 新增 `ensurePipeSeparator` + 串联到 `ensurePrefix` |

## 验证

用以下场景测试（社招/校招各一轮）：
- 带加粗：`- 基于 **Vue + Element UI**，开发模块` → 输出应保留 `**`
- 带 `||`：`### 信息技术有限公司 || 2021.07 – 至今` → 输出应保留 `||`
- 带加粗数字：`- 提升效率 **40%**` → 输出应保留 `**`
- 仅行前缀：`- 普通文本` → 行为不变
- 无格式：`普通文本` → 行为不变
